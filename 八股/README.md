## 每天怎么学

1. **先查前置**：标准答案里出现不懂的词，先去当天学习导航找到对应专题，不要跳过生词背整句。
2. **再读代码与图**：追踪对象创建、访问、转移和销毁，说明每一步改的是谁，以及为什么这样写。
3. **换一个使用场景**：说清什么时候有用、不满足哪些条件时不能用。每次可只学一个专题，详细资料分次完成。
4. **回到测试页口述**：先遮住答案，讲 30–90 秒，再核对“结论 → 原因 → 条件/例外 → 场景”，最后做代码变式。
5. **记录实际表现**：按 0–3 分填写，记下具体卡住的名词或条件。保留每天约 45–60 分钟的节奏时，将长专题拆到多次学习，不要求一天读完所有扩展。

例如回答智能指针时，先说明谁拥有对象，再说什么时候销毁，最后补一句线程安全边界。面试追问改变条件时，这条逻辑仍然能用。

**记忆建议**：让折叠区承担“先回忆，再核对”的作用。主动提取与间隔练习有研究支持，参考 [Learning Scientists 的学习建议](https://www.learningscientists.org/learning-scientists-podcast/2018/3/7/episode-14-how-students-can-use-spacing-and-retrieval-practice)。这里暂用学习后第 1、3、7、14、30 天复习；具体间隔按遗忘与自测调整，不保证是每个人的最佳安排。

| 分数 | 判断标准 |
| --- | --- |
| 0 | 无法回答，或关键结论错误 |
| 1 | 看过有印象，独立回答漏关键点 |
| 2 | 主结论正确，边界或代码需要提示 |
| 3 | 能解释机制、边界，并完成一个变式 |

新生成题初始为“未自测”；已经由用户填写分数的题按实际记录更新。2026-10-20 的自测已完成，详细学习与再次复测仍需分别记录。生成日期不等于已经学习，计划复习日期也不等于已复习。查看 [[题目索引|题目索引]]。

## 学习路线

| 阶段 | 主题 | 连接到的开发场景 |
| --- | --- | --- |
| 语言与资源 | 生命周期、RAII、复制移动、智能指针、STL、复杂度 | 行情消息所有权、订单对象、日志缓冲 |
| 并发正确性 | 数据竞争、锁、条件变量、原子、内存序 | 生产者消费者、跨线程消息交接 |
| Linux 与网络 | 进程线程、虚拟内存、IPC、TCP/UDP、非阻塞 I/O、epoll | 行情接入、连接管理、共享内存通信 |
| 性能分析 | 缓存、伪共享、分配、数据布局、perf、尾延迟 | 热路径分析、日志抖动、订单簿访问 |
| 综合工程 | Ring Buffer、LRU、线程池、订单簿、回放 | 讲清正确性、复杂度、测试与性能取舍 |

按知识依赖推进，不硬排“几天精通”。算法与工程手写穿插练习，基础概率与交易常识后续适量补充。
