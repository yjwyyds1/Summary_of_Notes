## CPP-VTABLE-001 · 虚表是类的还是对象的

> [!question] 问题 1 / 6 · 原帖问法
> “C++ 的多态怎么实现的？虚表是类的还是对象的？”
>
> 追问：一个对象里到底多存了什么？为什么多继承下把派生对象转成两个不同的基类指针，得到的地址可能不一样？

**原帖明确提及：** [滴滴 C++ 面经](https://www.iamshuaidi.com/4432.html) 一面原问；[美团面经](https://www.iamshuaidi.com/4321.html) 追问单继承与菱形继承的虚表分布。学习：[[学习/2026-10-22/01-虚表与对象内存布局]]。

> [!hint]- 卡住时再看
> 想“如果每个对象都存一整张表，一万个对象要多花多少内存”；再想多继承时 `B*` 为什么要指向对象中间的某个位置。

> [!tip]- 标准解答
> **面试口述（60–90 秒）**
>
> 多态靠“虚函数 + 指针/引用调用”实现。编译器给每个多态类生成一张虚函数表，表里是该类各虚函数的地址；每个对象里存一个指向本类虚表的指针，常见实现放在对象起始处。所以**表属于类，指针属于对象**：同类对象共享一张表。
>
> 调用 `base_ptr->f()` 时，编译器生成“取对象 vptr → 取表里第 k 项 → 间接调用”，运行时才知道进哪个函数，这就是动态绑定。
>
> 多继承时，派生对象里有多个基类子对象，每个多态基类子对象各需要一个 vptr，所以 `A*` 和 `B*` 指向同一对象的不同偏移。虚继承还会额外保存虚基类偏移。
>
> **关键点 / 易错点**
> - 标准只说“调用哪个函数”，不说虚表怎么排；布局是 ABI 细节（GCC/Clang 用 Itanium ABI）。
> - `sizeof` 变化：本机 `Base`（1 个 int + 虚函数）是 16，`C : A, B` 是 32。
> - 虚调用多一次间接寻址，常阻碍内联；`final` 或直接调用可帮编译器去虚化。
>
> **核对来源**：[N4659 class.virtual](https://timsong-cpp.github.io/cppwp/n4659/class.virtual)；实测数据见 [[学习/2026-10-22/示例验证]]。

> [!info]- 深挖与追问（选学）
> **“虚表在编译期还是运行期生成？”** 常见实现里表的内容在编译/链接期就固定，运行时只是读取。
>
> **“析构函数在虚表第几项？”** 不同 ABI 不同，Itanium ABI 里析构通常占两个槽位（完整对象析构与删除析构）。这类细节只在读汇编或排查崩溃时有用，面试说“它也是虚函数，占表项”即可。
>
> **“为什么崩溃栈里会出现 `vtable for X`？”** 通常是通过悬垂指针调用虚函数，vptr 已被释放后的内存覆盖。

- [ ] 能说清“表属于类、指针属于对象”，并解释多继承地址差异。

## CPP-CTOR-001 · 构造/析构里调用虚函数会怎样

> [!question] 问题 2 / 6 · 原帖问法
> “构造函数能否是虚函数？为什么？”
>
> 追问：在基类构造函数里调用一个被派生类覆盖的虚函数，会进哪个版本？析构函数里呢？基类析构不是虚函数，`delete base_ptr` 会怎样？

**原帖明确提及：** [拼多多 C++ 面经](https://www.iamshuaidi.com/30924.html) 原问“构造函数能否是虚函数”；[字节 C++ 实习面经](https://www.iamshuaidi.com/3488.html) 原问“虚析构函数”。学习：[[学习/2026-10-22/02-构造析构顺序与虚调用]]。

> [!hint]- 卡住时再看
> 构造是“从基类往派生类搭起来”，析构是“从派生类往基类拆下去”。想一下：搭到一半时，派生类的成员存不存在？

> [!tip]- 标准解答
> **面试口述**
>
> 构造函数不能是虚函数。虚调用要求对象已经存在、动态类型已知；而构造函数的工作就是创建这个对象，调用它的时候对象还不存在，逻辑上矛盾。派生类构造时先调基类构造，此刻 vptr 指向的是基类，所以基类构造函数里调用虚函数只会进基类版本。
>
> 析构也一样：进入 `~Base` 时派生部分已经销毁，虚调用只会到 `Base` 这一层。
>
> 基类如果会被 `delete` 基类指针，析构必须是虚函数，否则标准规定未定义行为，实践中派生类析构不执行、资源泄漏。析构函数默认 `noexcept`，抛异常通常直接 `terminate`。
>
> **关键点 / 易错点**
> - 构造顺序：基类 → 成员（按声明顺序）→ 函数体；析构反过来。
> - 构造抛异常时，已完成的基类/成员会被析构，对象自身的析构不执行。
> - 不要在构造函数里注册回调或启动线程，`this` 还是半成品。
>
> **核对来源**：[N4659 class.cdtor](https://timsong-cpp.github.io/cppwp/n4659/class.cdtor)、[expr.delete](https://timsong-cpp.github.io/cppwp/n4659/expr.delete)、[except.ctor](https://timsong-cpp.github.io/cppwp/n4659/except.ctor)。

> [!info]- 深挖与追问（选学）
> **“想要按类型创建对象怎么办？”** 用工厂函数或 `clone()` 虚函数 + 具体类注册表，而不是“虚构造函数”。
>
> **“析构函数能纯虚吗？”** 可以，但必须提供定义，否则派生类析构链接失败（纯虚析构同样要调用基类版本）。
>
> **“为什么统一写 `virtual ~Base() = default;`？”** 表达意图、成本低（本来就有 vptr），并让 `unique_ptr<Base>` 正确销毁派生对象。

- [ ] 能解释构造/析构期间虚调用只到当前层的原因，而不只是背结论。

## CPP-HIDE-001 · 重载、重写、隐藏

> [!question] 问题 3 / 6 · 原帖问法
> “函数重写、覆盖、隐藏有什么区别？”
>
> 追问：基类有 `virtual void f(int)` 和 `void f(double)`，派生类只写了 `void f(int) override`，此时 `derived.f(1.5)` 还能调到基类的 `double` 版本吗？

**原帖明确提及：** [顺丰 C++ 后端面经](https://www.iamshuaidi.com/31482.html) 二面原问。学习：[[学习/2026-10-22/03-重载重写与名字隐藏]]。

> [!hint]- 卡住时再看
> 三个词的差别在“在哪个作用域找名字”“参数是否相同”“是否 virtual”。

> [!tip]- 标准解答
> **面试口述**
>
> 重载是同一作用域里同名、参数列表不同的函数，编译期按实参选。重写（覆盖）是派生类重新实现基类虚函数，名字、参数、cv 限定都要一致，经指针/引用调用时按对象真实类型派发。隐藏是派生类声明了同名成员，把基类所有同名成员挡住，跟参数是否相同无关。
>
> 所以上面那个例子，`derived.f(1.5)` 会先找到 `Derived::f(int)`，`double` 被隐藏、隐式转成 `int` 调用；想恢复就写 `using Base::f;`。
>
> 避免覆盖失败：派生类写 `override`，签名不一致会直接编译报错。
>
> **关键点 / 易错点**
> - 返回类型不参与重载；默认参数静态绑定，虚函数不要写默认参数。
> - `final` 禁止继续重写，也能帮编译器去虚化。
> - 名字查找是“先找名字集合，再做重载决议”，不会跨作用域合并。
>
> **核对来源**：[N4659 class.member.lookup](https://timsong-cpp.github.io/cppwp/n4659/class.member.lookup)、[class.virtual](https://timsong-cpp.github.io/cppwp/n4659/class.virtual)。

> [!info]- 深挖与追问（选学）
> **“加 `const` 会怎样？”** 签名变了，构成隐藏而不是重写；加 `override` 会报错。
>
> **“虚函数能用模板吗？”** 成员函数模板不能是虚函数。

- [ ] 能各举一个例子，并说明 `using` 与 `override` 的作用。

## CPP-STATIC-001 · static 的四种用法

> [!question] 问题 4 / 6 · 原帖问法
> “说说 static 在 C++ 里的作用。”
>
> 追问：函数内的 `static` 变量什么时候初始化？多线程同时第一次调用安全吗？全局对象初始化顺序问题怎么用 static 解决？

**原帖明确提及：** [顺丰 C++ 后端面经](https://www.iamshuaidi.com/31482.html) 一面把 static 列在基础八股里。学习：[[学习/2026-10-22/04-static的四种用法]]。

> [!hint]- 卡住时再看
> 分别想：函数里的局部变量、类里的数据成员、类的成员函数、命名空间里的变量。

> [!tip]- 标准解答
> **面试口述**
>
> static 有四种身份：函数内局部变量（静态存储期，第一次执行到才初始化）、类静态数据成员（全类一份，C++17 可 `inline static` 在类内定义）、静态成员函数（没有 `this`，只能直接访问静态成员）、命名空间作用域的 static（内部链接，只在本翻译单元可见，现在更推荐匿名命名空间）。
>
> C++11 起，函数内静态局部变量的初始化是线程安全的：多个线程同时第一次进入，只有一个线程执行初始化，其他等待。这叫 magic statics。
>
> 它还能解决全局对象跨翻译单元初始化顺序不确定的问题：把全局对象改成函数内 static，构造发生在第一次使用时。
>
> **关键点 / 易错点**
> - 初始化线程安全 ≠ 对象操作线程安全，后续读写仍要同步。
> - 静态成员的析构发生在程序退出阶段，别让其他线程还在用它。
> - 模板类的静态成员每个实例化一份。
>
> **核对来源**：[N4659 stmt.dcl](https://timsong-cpp.github.io/cppwp/n4659/stmt.dcl)、[class.static.data](https://timsong-cpp.github.io/cppwp/n4659/class.static.data)、[basic.start.dynamic](https://timsong-cpp.github.io/cppwp/n4659/basic.start.dynamic)。

> [!info]- 深挖与追问（选学）
> **“单例为什么常用函数内 static？”** 懒初始化、线程安全、不用手动管释放顺序。缺点是退出阶段析构顺序仍可能踩坑，可用“有意不析构”或显式生命周期管理。

- [ ] 能说出四种用法，并解释“初始化线程安全”的边界。

## CPP-ALIGN-001 · 空类为什么是 1

> [!question] 问题 5 / 6 · 原帖问法
> “空类 `sizeof` 是多少？为什么不是 0？”
>
> 追问：`struct { char c; int i; char d; }` 在 x86-64 上多大？换个成员顺序为什么变小？含虚函数的类又怎么算？

**原帖明确提及：** [顺丰 C++ 后端面经](https://www.iamshuaidi.com/31482.html) 把“内存分部”列为八股；[携程 C++ 面经](https://www.iamshuaidi.com/31681.html) 记有 float 占几字节、浮点如何存储。空类与对齐规则属于该方向的常考延伸，本库标为扩展。学习：[[学习/2026-10-22/05-内存对齐与sizeof]]。

> [!hint]- 卡住时再看
> 三个规则：成员按自身对齐放、结构体对齐取最大成员、总大小补齐到对齐倍数。

> [!tip]- 标准解答
> **面试口述**
>
> 空类大小是 1。标准要求同类型的两个不同对象地址必须不同，所以哪怕没有成员也要占至少一个字节。作为基类时可以被优化掉，不额外占空间（空基类优化）。
>
> 对齐规则三条：每个成员的偏移是它自身对齐的倍数；结构体对齐等于最大成员对齐；总大小补齐到对齐的倍数。所以 `char,int,char` 是 12 字节，`int,char,char` 是 8 字节，同样的成员换顺序就省了 4 字节。
>
> 含虚函数的类还要加 vptr，本机 8 字节，再按对齐补齐。
>
> **关键点 / 易错点**
> - 位域、`#pragma pack`、`alignas` 都会改变结果，别背公式，用 `sizeof` 验证。
> - 普通 `malloc` 只保证 `max_align_t` 对齐，过对齐类型要用 C++17 的 aligned new。
> - 协议结构体不能直接依赖默认对齐与字节序。
>
> **核对来源**：[N4659 basic.align](https://timsong-cpp.github.io/cppwp/n4659/basic.align)、[intro.object](https://timsong-cpp.github.io/cppwp/n4659/intro.object)、[class.mem](https://timsong-cpp.github.io/cppwp/n4659/class.mem)。

> [!info]- 深挖与追问（选学）
> **“怎么减少填充？”** 按对齐从大到小排成员；热路径结构体可以按缓存行对齐并考虑 SoA。
>
> **“`#pragma pack(1)` 有什么风险？”** 取消填充会造成未对齐访问，在部分架构上出错或变慢，也破坏 ABI 兼容。

- [ ] 能现场手算一个含 `char/int/double` 的结构体大小，并解释每段填充。

## CPP-CAST-001 · 四种类型转换

> [!question] 问题 6 / 6 · 本库扩展题
> “C++ 有哪几种类型转换？分别用在什么场景？”
>
> 追问：`dynamic_cast` 失败时怎么表现？它为什么要求源类型是多态类型？为什么多继承下不能用 `reinterpret_cast` 做向下转换？

**原帖明确提及：** 本日原帖没有直接问“四种 cast”，这是对象模型方向的常考延伸，**本库标为扩展题**，不计作候选人原问。学习：[[学习/2026-10-22/06-四种类型转换与RTTI]]。

> [!hint]- 卡住时再看
> 按“意图”分：改数值/相关类型、运行时查类型、去 const、改位模式。

> [!tip]- 标准解答
> **面试口述**
>
> 四种：`static_cast` 用于相关类型之间的转换，包括数值转换、`void*` 转换、基类派生类转换、显式构造函数调用，编译期只检查类型关系，不做运行时检查。`dynamic_cast` 用于多态类型的安全向下或交叉转换，运行时核对，指针失败返回空，引用失败抛 `bad_cast`。`const_cast` 只增删 cv 限定。`reinterpret_cast` 按位重新解释，常用于指针与整数、无关指针类型之间，不做继承偏移调整。
>
> `dynamic_cast` 要求源类型含虚函数，因为运行期类型信息（RTTI）通常挂在虚表上。
>
> C 风格转换会按顺序尝试 `const_cast`、`static_cast`、`reinterpret_cast` 的组合，看不出意图也不好搜索，工程里不用。
>
> **关键点 / 易错点**
> - `static_cast` 向下转换类型不符时是未定义行为。
> - `const_cast` 去掉 const 后写“本来就是 const”的对象是未定义行为。
> - 热路径少用 `dynamic_cast`，可改用虚函数、`std::variant` 或类型标签。
>

## EX-20261022-001 · 给行情过滤器补上接口约束

> [!question] 小练习 · 先独立写，再看答案
> 下面这段“行情过滤器”有编译错误，也有能编译但危险的写法：
>
> ```cpp
> struct Quote { double price; int qty; };
> class Filter {
> public:
>     virtual void apply(Quote quote) = 0;
>     ~Filter() {}
> };
> class MinPrice : public Filter {
> public:
>     explicit MinPrice(double p) : min_price_(p) {}
>     void apply(Quote quote) override;
> private:
>     double min_price_;
> };
> void run(Filter filter);
> ```
>
> 要求：指出问题 → 改成“不可拷贝、虚析构、参数不复制” → 说出 `sizeof(MinPrice)` → 解释禁止拷贝能防住什么真实故障。

**性质：** 本库自拟练习，用来串起虚析构、切片、对齐三个考点，不是原帖原题。详解：[[学习/2026-10-22/07-练习-过滤器接口约束]]。

> [!hint]- 卡住时再看
> 抽象类能不能按值存在？按值传基类会复制哪些部分？`delete` 基类指针时需要什么才能正确销毁？

> [!tip]- 参考答案
> **问题定位**
> 1. `~Filter()` 不是虚析构：经 `Filter*` 删除派生对象是未定义行为。
> 2. `void run(Filter filter)` 编译失败，因为 `Filter` 是抽象类；即使不是抽象类，按值传参也会切片。
> 3. `apply(Quote quote)` 每次都复制结构体，应改 `const Quote&`。
>
> **修复要点**
> - `virtual ~Filter() = default;`
> - `Filter(const Filter&) = delete; Filter& operator=(const Filter&) = delete;`
> - `virtual void apply(const Quote& quote) const = 0;`
> - `void run(const Filter& filter);`
>
> **`sizeof`**：`Filter` 8（只有 vptr），`MinPrice` 16（vptr + double）。
>
> **为什么禁拷贝**：多态基类被按值复制会切片，派生部分丢失、虚调用退化成基类版本；放进 `vector<Filter>` 后全部元素都变成基类。删掉拷贝让编译器在编译期拦住。
>
> 完整代码：[[学习/2026-10-22/示例代码/07_filter_interface|07_filter_interface]]。
