# 练习：手写固定大小对象池

← [[学习/学习导航/2026-10-25-学习导航|今日导航]] · [[八股测试/2026-10-25#EX-20261025-001|回到练习题]] · 参考答案：[[学习/2026-10-25/示例代码/04_object_pool|04_object_pool 阅读版]]

## 题目

实现一个固定容量 `N` 的对象池 `ObjectPool<T, N>`，要求：

1. `T* acquire()` / `T* acquire(args...)`：在池内存储上**构造**一个 `T`，池满返回 `nullptr`；
2. `void release(T*)`：先**析构**再回收存储，空指针直接忽略；
3. 存储必须满足 `T` 的对齐要求；
4. 池对象本身禁止拷贝；
5. 提供 `available()`、`outstanding()`、`capacity()` 三个查询。

再写一个测试程序，覆盖：正常借还、池满、归还后地址复用、析构次数正确。

最后回答三个追问：

- 为什么 `storage_` 不能写成 `T storage_[N]`？
- 如果两个线程同时 `acquire`，当前实现会出什么问题？
- 池析构时如果有对象没归还，会发生什么？

## 先自己想

提示：`std::byte` 数组 + `alignas(T)` 是常见写法；placement new 需要 `<new>`；释放时必须显式调用 `obj->~T()`。

> [!tip]- 参考答案
>
> **核心结构**
>
> ```cpp
> alignas(T) std::byte storage_[BlockCount][sizeof(T)];
> std::vector<void*> free_slots_;
> ```
>
> - `std::byte` 是“原始字节”，不会被当成 `T` 构造；
> - `alignas(T)` 保证每块起始地址满足 `T` 的对齐；
> - 空闲表里只存地址，不存对象。
>
> **`acquire` / `release`**
>
> ```cpp
> T* acquire() {
>     if (free_slots_.empty()) return nullptr;
>     void* slot = free_slots_.back();
>     free_slots_.pop_back();
>     return new (slot) T();
> }
>
> void release(T* object) {
>     if (object == nullptr) return;
>     object->~T();
>     free_slots_.push_back(object);
> }
> ```
>
> **三个追问的回答**
>
> 1. `T storage_[N]` 会真正构造 N 个 `T`，池子一开始就付出 N 次构造代价，而且对象生命周期由编译器管理，无法“按需构造、按需析构”。
> 2. 两个线程同时 `acquire` 会同时读到同一个 `free_slots_.back()`，造成同一块存储被构造两次——数据竞争 + 未定义行为。要么外部加锁，要么改线程本地池，要么用无锁栈（并注意 ABA）。
> 3. 池析构不会替未归还对象调用析构函数；如果有需要释放的资源，就会泄漏。工程上要么在析构时断言 `outstanding_ == 0`，要么提供 `for_each_outstanding` 强制清理。
>
> **完整实现与运行结果**：[[学习/2026-10-25/示例代码/04_object_pool|04_object_pool]]，本机运行可见“归还后再次 acquire 拿到同一地址”。
