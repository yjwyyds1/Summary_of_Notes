# 练习：给行情过滤器接口补上正确的约束

← [[学习/学习导航/2026-10-22-学习导航|今日导航]] · [[八股测试/2026-10-22#EX-20261022-001|回到练习题]] · 答案代码：[[学习/2026-10-22/示例代码/07_filter_interface|07_filter_interface 阅读版]]

## 题目

下面是一个行情过滤器的初版，作者想做到“配置决定用哪个过滤器，运行时替换实现”。这段代码有编译错误，也有能编译但危险的写法：

```cpp
struct Quote { double price; int qty; };

class Filter {
public:
    virtual void apply(Quote quote) = 0;   // (1)
    ~Filter() {}                            // (2)
};

class MinPrice : public Filter {
public:
    explicit MinPrice(double min_price) : min_price_(min_price) {}
    void apply(Quote quote) override {      // (3)
        if (quote.price >= min_price_) { std::cout << quote.price << '\n'; }
    }
private:
    double min_price_ = 0.0;
};

void run(Filter filter);                    // (4)
```

要求：

1. 指出 (1)~(4) 各自的问题：哪一处编译不过，哪一处能编译但有隐患。
2. 改成：基类不可拷贝、析构为虚、接口参数不复制整个 `Quote`。
3. 说明修改后 `sizeof(MinPrice)` 在 x86-64 / GCC 下是多少，为什么。
4. 说明为什么“基类不可拷贝”能防止一类真实故障。

## 先自己想 5 分钟

提示：想一想“按值传基类会发生什么”“delete 基类指针时派生类析构会不会跑”“拷贝一个多态基类对象会得到什么类型”。

> [!tip]- 参考答案
>
> **(1) 参数按值传递**：`apply(Quote quote)` 本身能编译，但每次调用复制整个结构体。更关键的是，如果将来换成按值传基类引用类型的参数，会触发**对象切片**。工程上改成 `const Quote&`。
>
> **(2) 析构不是虚函数**：`~Filter() {}` 不是 virtual。通过 `Filter*` 删除 `MinPrice` 对象时行为未定义，实践中派生类部分不会被析构。改成 `virtual ~Filter() = default;`。
>
> **(3) 看起来没问题**：`override` 写对了。真正的隐患在 (4)。
>
> **(4) `void run(Filter filter)` 编译失败**：`Filter` 是抽象类（含纯虚函数），不能按值创建；即使 `Filter` 不是抽象的，按值传参也会**切片**——只复制基类子对象，派生类的 `min_price_` 丢失，`apply` 调到的也不是派生版本。
>
> **修好后的形状**：
>
> ```cpp
> struct Quote { double price; int qty; };
>
> class Filter {
> public:
>     virtual ~Filter() = default;                       // 虚析构
>     Filter(const Filter&) = delete;                    // 禁止拷贝构造
>     Filter& operator=(const Filter&) = delete;         // 禁止拷贝赋值
>     Filter() = default;
>     virtual void apply(const Quote& quote) const = 0;  // 不复制、不修改
> };
>
> class MinPrice : public Filter {
> public:
>     explicit MinPrice(double min_price) : min_price_(min_price) {}
>     void apply(const Quote& quote) const override {
>         if (quote.price >= min_price_) { std::cout << quote.price << '\n'; }
>     }
> private:
>     double min_price_ = 0.0;
> };
>
> void run(const Filter& filter);   // 引用：不切片，也不要求可拷贝
> ```
>
> **`sizeof(MinPrice)`**：x86-64 / GCC 下是 **16** = 8 字节 vptr + 8 字节 `double`。基类 `Filter` 没有数据成员，只有 vptr，所以不额外增加基类成员；派生类的 `double` 恰好 8 字节对齐。
>
> **为什么禁止拷贝**：多态基类的拷贝会产生“静态类型是基类、动态类型丢失”的对象，也就是切片；一旦它被加入容器（`std::vector<Filter>`），所有元素都变成基类，虚调用全部失效。把拷贝删掉，让编译器在编译期报错，比运行时查 bug 便宜得多。

## 检查清单

- [ ] 能说出“抽象类不能按值传参”是编译错误，而“非抽象基类按值传参”是切片。
- [ ] 能解释虚析构缺失为什么是未定义行为，而不只是“内存泄漏”。
- [ ] 能从 vptr + 成员推出 `sizeof`，而不是背数字。
- [ ] 知道 `= delete` 的拷贝控制为什么要同时删拷贝构造与拷贝赋值。
