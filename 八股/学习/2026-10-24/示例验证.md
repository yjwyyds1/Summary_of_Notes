## 实际执行

在用户正在运行的 **WSL Ubuntu** 中，使用 `g++ (Ubuntu 15.2.0-16ubuntu1) 15.2.0`，逐个以 `-std=c++17 -Wall -Wextra -pedantic -O0 -pthread` 编译七份保存的 `.cpp`，七个程序均退出码 0，编译输出无警告。Linux 专属的 `fork` 和 `pipe` 分支确实执行了。二进制输出位置为 WSL 临时目录 `/tmp/cpp-notes-20261024/`，不属于笔记库。

| 程序 | WSL 实际输出的关键行 | 验证含义 |
| --- | --- | --- |
| 01_process_thread | `thread changed parent value: 2`；`parent after child exit: 1` | 线程共享更新；父进程变量不随子进程更改 |
| 02_pipe_ipc | `parent received: ABC` | 子进程经匿名管道向父进程传字节 |
| 03_virtual_memory | `model physical address=0x7234` | 教学算术模型断言成立，不代表读取系统页表 |
| 04_deadlock | `final balances: 100 100` | 本次两线程转账结束且总额断言成立 |
| 05_condition_variable | `consumed: 42` | 共享状态配合条件变量交接 |
| 06_thread_pool | `completed tasks: 3` | 教学任务池排空三项任务 |
| 07_bounded_queue | `1 2 3` | 本次有界队列按顺序消费 |

Windows 上另用 MinGW g++ 13.1 编译并运行全部七份的可用分支，结果也为退出码 0；`01/02` 在 Windows 只输出 Linux 专属路径提示。Windows 初次编译 `04` 曾提示 mutex 聚合成员未显式初始化，随后源码改为 `mutex{}`；最终 WSL 编译无此警告。

**验证边界**：单次正常运行不能证明所有并发交错都正确，不能证明无数据竞争、无异常边界问题，也不是性能测试。示例中的线程池和管道仅供教学；生产代码还需错误处理、容量、异常与关闭策略。
