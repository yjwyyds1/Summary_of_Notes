## 先把词讲明白

**执行上下文**是“这条执行路径暂停后还能从原处继续”的必要状态，包括程序计数器（下一步指令位置）、通用寄存器、栈指针及调度状态。**上下文切换**时，内核保存当前任务的状态，选另一个可运行任务，再恢复后者之前保存的状态。CPU 本身的寄存器数量有限，不可能同时让每条线程都占着同一组寄存器。

**进程**有自己的地址空间，同进程**线程**共用地址空间，但各有栈和执行状态。因此线程 A 换线程 B，即使仍是同进程，也要切执行状态；若换到另一进程，通常还要切换地址空间相关状态。实际开销受 CPU、内核、缓存和负载影响，不能许诺固定的进程/线程倍率。换走一个任务并不等于复制它整个内存。

```mermaid
flowchart LR
  A["任务A正在运行：寄存器/指令位置"] --> B["内核保存A的执行状态"]
  B --> C["调度器选择就绪的任务B"]
  C --> D["恢复B的执行状态"]
  D --> E["任务B从上次位置继续"]
```

## 为什么系统调用与上下文切换要分开数

系统调用是**当前任务请求内核服务**，它会进入内核态；如果无需等待或被调度器换走，内核可返回同一任务。上下文切换是**谁占用 CPU 改变**。两者可能同时发生，也可能只发生前者。昨天讲过的 [syscall 入口](https://man7.org/linux/man-pages/man2/intro.2.html) 给出系统调用定义。比如一个短的查询调用可能很快返回；等待 I/O 则可能让任务暂时不可运行。

**自愿切换**常发生在任务等待资源或主动让出时；**非自愿切换**是运行中的任务被调度器抢占等。Linux 的 `getrusage` 可以读取累计的 `ru_nvcsw` 与 `ru_nivcsw`，分别报告这两类次数。[getrusage(2)](https://man7.org/linux/man-pages/man2/getrusage.2.html) 的 `RUSAGE_SELF` 是调用进程所有线程的合计；下面只有主线程，便于理解。次数并不告诉我们一次切换用了多少纳秒。

## 先预测，再运行

下面先读一次累计值，主线程短暂等待三次，再读一次，打印两次差值。主动睡眠通常会带来自愿切换，但实际增量、是否有抢占、何时恢复都受环境影响，**不能用固定输出作为标准保证**。

```cpp
// 目的：读取 Linux 的上下文切换计数，观察主动等待前后的变化。
// 平台：Linux + C++17；getrusage 及两个切换计数字段属于这里使用的平台接口。
// 先修：结构体成员、取地址 &、const，以及毫秒表示时间长度。
// 步骤：读累计计数 -> 短暂等待三次 -> 再读计数 -> 输出两次读取的差值。
// 观察：自愿切换通常增加，非自愿切换可以为 0；具体数字不能事先写死。
// 程序只使用主线程，不创建子进程、不制造大量负载，正常运行约几十毫秒。

#include <chrono>        // std::chrono::milliseconds：带“毫秒”单位的时间长度。
#include <cstdio>        // std::perror：打印 getrusage 失败时的系统错误。
#include <iostream>      // std::cout：测量结束后再打印，减少输出对计数的干扰。
#include <thread>        // std::this_thread::sleep_for：让当前线程等待，不创建新线程。
#include <sys/resource.h> // Linux getrusage、rusage、RUSAGE_SELF 的声明。

int main() {
    // before/after 各保存一份内核累计资源统计；{} 使成员有已知初值。
    struct rusage before{};
    struct rusage after{};

    // RUSAGE_SELF 统计本进程所有线程之和；本例只有主线程，解释范围较简单。
    // &before 把对象地址交给函数，让它填写结果；返回 -1 表示失败。
    if (::getrusage(RUSAGE_SELF, &before) == -1) {
        std::perror("getrusage(before)");
        return 1;
    }

    // constexpr 表示编译时就能确定的常量；只等待三次，避免变成压力测试。
    constexpr int rounds = 3;
    constexpr int wait_ms = 20;
    for (int round = 0; round < rounds; ++round) {
        // sleep_for 让当前线程阻塞等待，CPU 可以执行其他可运行线程或空闲任务。
        // 实际恢复执行还要等到调度机会，因此不能承诺恰好在 20ms 时回来。
        std::this_thread::sleep_for(std::chrono::milliseconds(wait_ms));
    }

    if (::getrusage(RUSAGE_SELF, &after) == -1) {
        std::perror("getrusage(after)");
        return 1;
    }

    // ru_nvcsw 是自愿切换累计次数，ru_nivcsw 是非自愿切换累计次数。
    // 字段类型为 long；const 表示下面的输出不能意外修改这两个差值。
    const long voluntary = after.ru_nvcsw - before.ru_nvcsw;
    const long involuntary = after.ru_nivcsw - before.ru_nivcsw;

    // 此处已经拿到 after；下面的输出即使发生阻塞，也不计入刚才的测量区间。
    std::cout << "等待次数 = " << rounds << ", 每次请求 " << wait_ms << "ms\n";
    std::cout << "自愿上下文切换增量 = " << voluntary << '\n';
    std::cout << "非自愿上下文切换增量 = " << involuntary << '\n';
    std::cout << "这些是次数，不是一次切换的耗时，也不是系统调用次数\n";
    return 0;  // 没有额外线程或子进程，程序自然结束。
}
```

代码里的 `&before` 是把结构体地址交给内核接口，让接口填写；`const long` 保证本地差值之后不被改写；`chrono::milliseconds` 明确时间单位。`sleep_for` 不创建新线程，只让当前线程等待。先取得 `after` 再打印，避免打印期间的切换混入观测窗口。

**量化/服务场景**：如果线程数远多于可同时运行的 CPU 执行位置，或工作线程频繁阻塞，切换和排队都可能影响尾延迟。但看到切换次数增加，必须结合吞吐、延迟、CPU 使用、阻塞位置与负载再判断问题，不能仅凭这一指标断言“性能差”。

**口述总结**：切换要保存当前执行位置和寄存器等状态，再恢复下一任务；同进程线程共享地址空间，跨进程还涉及地址空间切换，但都要切执行状态。系统调用进入内核不一定更换正在运行的任务。`getrusage` 可看切换次数，不能单靠次数推断单次成本或故障原因。
