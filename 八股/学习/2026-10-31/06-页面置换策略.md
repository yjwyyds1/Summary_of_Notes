## 2 先分清页、页框和缺页

可以把物理内存想成数量有限的座位，而要用的页面可能比座位多。某个暂时不在座位上的页面将要被访问时，如果没有空座位，就需要考虑让哪一页先离开。**“选谁离开”是策略，“怎样安全腾位、恢复映射”是机制。**

| 词 | 普通解释 | 本文采用的含义 |
| --- | --- | --- |
| 页 page | 按固定粒度分组的数据 | 虚拟地址空间中的页面；本例用整数 1/2/3 表示不同页 |
| 页框 frame | 能装一页的物理位置 | 页框身份不变，装在里面的页可以替换 |
| 驻留 resident | 当前已在内存里 | 本例访问它就是命中，不新增模拟缺页 |
| 缺页 page fault | 当前映射条件不满足，需要内核处理 | 本例只模拟“访问页未驻留”，真实缺页还有其他原因 |
| 受害页 victim | 为腾空间而选中的旧页 | 名字不表示该页错误，只表示本次先回收它 |
| 局部性 | 最近用过的东西可能很快再用 | 置换策略利用这种倾向，但它不是每段访问序列都满足的保证 |
| 脏页 dirty page | 内存里的内容被修改过 | 相对于可恢复它的后备副本有更新，不能任意丢掉更新 |
| 抖动 thrashing | 大部分时间忙于反复换来换去 | 有用页面集合放不下时，频繁缺页和回收妨碍实际工作 |

真实系统中，**缺页不等于非法地址，也不等于一定从磁盘读**。合法的首次分配、写时复制和已有可用缓存等情况也可能进入缺页处理。反过来，TLB 没有缓存某个映射，但页表已有有效驻留映射时，也不能直接叫“页被换出了”。机制回顾见 [OSTEP 第 21 章：Beyond Physical Memory: Mechanisms，§21.2–21.3](https://pages.cs.wisc.edu/~remzi/OSTEP/vm-beyondphys.pdf)及 [Linux 内存概览](https://docs.kernel.org/admin-guide/mm/concepts.html)。

```mermaid
flowchart LR
    A[访问一个合法页面] --> B{当前是否驻留}
    B -->|是| C[命中并记录访问信息]
    B -->|否| D[本模型计一次缺页]
    D --> E{是否有可用空框}
    E -->|有| H[装入或建立所需页面]
    E -->|无| F[策略选择可回收受害页]
    F --> G[按页面类型保留必要内容并释放页框]
    G --> H
    H --> I[建立映射后继续访问]
```

图是教学顺序；实际内核可能提前在后台回收并维护空闲页，不必每次等缺页发生后才开始挑页。

## 3 四个常见名字，分别依赖什么信息

| 策略 | 淘汰谁 | 保留什么信息 | 主要边界 |
| --- | --- | --- | --- |
| FIFO，先进先出 | 最早装入内存的页 | 装入顺序 | 命中不会刷新顺序；最早装入的页可能仍很热门 |
| LRU，最近最少使用 | 最近一次访问距今最远的页 | 精确的最近访问顺序 | 精确维护并不免费；用户态 LRU 容器不能直接代表内核页回收 |
| Clock，时钟/第二次机会 | 环形扫描中未获得第二机会的页 | 环形指针、每页引用位 R | 是对近期使用的近似，不记录完整时间先后 |
| OPT/MIN，最优基准 | 未来最晚再被访问的页 | 完整未来访问序列 | 离线比较可用，在线系统一般不可能预知未来 |

FIFO、Clock、最优比较和 Belady 现象的技术依据是 [OSTEP 第 22 章：Beyond Physical Memory: Policies，§22.2–22.9](https://pages.cs.wisc.edu/~remzi/OSTEP/vm-beyondphys-policy.pdf)。下面用本库的短序列讲 Clock，再用教材中的经典序列独立计算 FIFO。

### FIFO：不要把“装入”误写成“访问”

设只有 3 个页框，按顺序访问 `1,2,3,1,4`。前三次装满，装入顺序仍是 `1,2,3`；第四次访问 1 命中，**FIFO 不移动它**；访问 4 缺页后仍淘汰 1，成为 `2,3,4`。如果命中 1 就把它移到队尾，你写的已经不是这一版 FIFO。

### Clock：引用位不是计数器，也不是时间戳

规定本篇变体：空框优先占用；任何访问把该页的 `R` 置 1；命中不动指针；要找受害页时，从指针开始，遇 `R=1` 就清零并前进，遇 `R=0` 就替换；装入新页后 `R=1`，指针前进一格。

`R=1` 只表示“从上次清零以来至少用过一次”。访问 1 次和 100 次都可能是 1；两个 R 都为 1，也不知道哪个更近，所以它不是精确 LRU。硬件/内核如何采集访问位依赖体系结构；本程序通过普通 C++ 赋值模拟这件事。

用 `页号:R` 表示框内状态，初始指针指向 0 号框：

| 访问 | 结果 | 0 号框 | 1 号框 | 2 号框 | 下次指针 |
| --- | --- | --- | --- | --- | --- |
| 1 | 缺页，占空框 | 1:1 | 空 | 空 | 1 |
| 2 | 缺页，占空框 | 1:1 | 2:1 | 空 | 2 |
| 3 | 缺页，占空框 | 1:1 | 2:1 | 3:1 | 0 |
| 1 | 命中，R 仍是 1 | 1:1 | 2:1 | 3:1 | 0 |
| 4 | 缺页，扫一圈清零后替换 1 | 4:1 | 2:0 | 3:0 | 1 |
| 2 | 命中，把 2 的 R 置 1 | 4:1 | 2:1 | 3:0 | 1 |
| 5 | 缺页，给 2 第二机会，替换 3 | 4:1 | 2:0 | 5:1 | 0 |

第 5 次访问最容易卡住：第一次看到框 0 的 `1:1`，先改为 `1:0`；继续清框 1、2；回到框 0 时看到 `1:0`，终于选中它。不是看到所有 R 都为 1 就永远找不到页。在本串行模拟里一次扫描最多清掉一圈，再找到一个可替换框。

## 4 反例：FIFO 的内存增多，缺页也可能增多

固定访问序列 `1,2,3,4,1,2,5,1,2,3,4,5`，从空内存开始。只改变页框数量，其余不变。

下表把每次访问后的 FIFO 队列按“最早装入 → 最晚装入”列出。`F` 表示缺页，`H` 表示命中；首次装入也计缺页。

| 访问 | 3 框结果及队列 | 4 框结果及队列 |
| --- | --- | --- |
| 1 | F：1 | F：1 |
| 2 | F：1 2 | F：1 2 |
| 3 | F：1 2 3 | F：1 2 3 |
| 4 | F：2 3 4 | F：1 2 3 4 |
| 1 | F：3 4 1 | H：1 2 3 4 |
| 2 | F：4 1 2 | H：1 2 3 4 |
| 5 | F：1 2 5 | F：2 3 4 5 |
| 1 | H：1 2 5 | F：3 4 5 1 |
| 2 | H：1 2 5 | F：4 5 1 2 |
| 3 | F：2 5 3 | F：5 1 2 3 |
| 4 | F：5 3 4 | F：1 2 3 4 |
| 5 | H：5 3 4 | F：2 3 4 5 |
| 合计 | 9 次缺页 | 10 次缺页 |

这叫 **Belady 异常**。它反驳的是“任何置换规则下，增加页框都一定不会增加缺页”，不是说给电脑加内存一般会变慢。固定同一序列、从空状态开始时，精确 LRU 具有包含关系：更大容量的驻留集合包含更小容量的集合，因而没有这种异常；本篇不重新实现旧 LRU 练习。

## 5 完整注释源码

文件：[[学习/2026-10-31/示例代码/06_page_replacement|Markdown 阅读版]] · [[学习/2026-10-31/示例代码/06_page_replacement.cpp|可编译源码]]。C++17；代码中的“页”只是整数，没有调用内核管理真实内存的接口。

```cpp
// 用途：模拟 FIFO 与 Clock 的受害页选择；用已知序列核对缺页次数。
// 先修：vector/deque、循环、bool；这里只保存整数页号，不操作真实页表。
// 模型：页框数固定；初始全空；每次访问一个页；未驻留就计一次模拟缺页。
// 不模拟脏页、磁盘、共享页、并发或预取；不是 Linux 内核的实际回收实现。
// 观察：FIFO 增加页框未必减少缺页；Clock 的引用位只有 0/1，不是精确访问排序。

#include <algorithm>  // std::find：在线性容器里查找页号。
#include <cassert>    // assert：核对手算值；不要定义 NDEBUG。
#include <cstddef>    // std::size_t：页框数量、下标和缺页计数的类型。
#include <deque>      // std::deque：从队头淘汰最早装入的页。
#include <iostream>   // std::cout：打印固定模拟结果。
#include <stdexcept>  // std::invalid_argument：拒绝零页框，避免取模除零。
#include <vector>     // std::vector：保存访问序列及固定数量页框。

// refs 是只读访问序列；capacity 是可使用的页框数；返回模拟缺页次数。
std::size_t fifo_faults(const std::vector<int>& refs, std::size_t capacity) {
    if (capacity == 0) {
        throw std::invalid_argument("capacity must be positive");
    }
    std::deque<int> resident;  // 队头最早装入，队尾最近装入；不是最近访问顺序。
    std::size_t faults = 0;
    for (int page : refs) {
        // find 返回 end() 表示没有找到。命中时什么也不挪动，这是 FIFO 的关键。
        if (std::find(resident.begin(), resident.end(), page) != resident.end()) {
            continue;
        }
        ++faults;
        if (resident.size() == capacity) {
            resident.pop_front();  // 满了才淘汰；仍有空框时直接装入即可。
        }
        resident.push_back(page);
    }
    return faults;
}

struct Frame {
    int page = 0;          // 存放的页号；只有 occupied 为 true 才有意义。
    bool referenced = false; // 自上次清零后是否被访问过，俗称引用位 R。
    bool occupied = false;   // 用单独标记区分空框，避免拿某个合法页号当“空”。
};

struct ClockResult {
    std::size_t faults = 0;
    std::vector<Frame> frames;  // 下标就是页框号，替换只修改该框的内容。
    std::size_t hand = 0;       // 下次找受害页从这里开始，像钟表指针一样绕回。
};

ClockResult clock_replace(const std::vector<int>& refs, std::size_t capacity) {
    if (capacity == 0) {
        throw std::invalid_argument("capacity must be positive");
    }
    ClockResult result;
    result.frames.resize(capacity);  // 创建 capacity 个 Frame，按成员默认值初始化。
    for (int page : refs) {
        bool hit = false;
        for (Frame& frame : result.frames) {  // & 表示直接修改页框，不是修改副本。
            if (frame.occupied && frame.page == page) {
                frame.referenced = true;    // 读取或写入都算访问，命中后重新置 1。
                hit = true;
                break;
            }
        }
        if (hit) {
            continue;  // 本变体在命中时不移动指针。
        }
        ++result.faults;
        // 空框直接用；R=0 的旧框可替换；R=1 则清零并给它一次第二机会。
        while (result.frames[result.hand].occupied &&
               result.frames[result.hand].referenced) {
            result.frames[result.hand].referenced = false;
            result.hand = (result.hand + 1) % capacity; // % 让末尾绕回下标 0。
        }
        result.frames[result.hand] = Frame{page, true, true};
        // 新页刚刚被访问过，所以 R=1；替换完成后指针前移一格。
        result.hand = (result.hand + 1) % capacity;
    }
    return result;
}

int main() {
    // 经典 Belady 序列：相同访问顺序、相同 FIFO 规则，只改变页框数量。
    const std::vector<int> classic{1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5};
    const std::size_t fifo3 = fifo_faults(classic, 3);
    const std::size_t fifo4 = fifo_faults(classic, 4);
    assert(fifo3 == 9);
    assert(fifo4 == 10);

    // 这个短序列专门观察“第二机会”：最终 Clock 留住了刚访问过的页 2。
    const std::vector<int> refs{1, 2, 3, 1, 4, 2, 5};
    const ClockResult result = clock_replace(refs, 3);
    assert(result.faults == 5);
    assert(result.hand == 0);
    assert(result.frames[0].page == 4 && result.frames[0].referenced);
    assert(result.frames[1].page == 2 && !result.frames[1].referenced);
    assert(result.frames[2].page == 5 && result.frames[2].referenced);
    assert(fifo_faults({}, 3) == 0 && clock_replace({}, 3).faults == 0);
    assert(fifo_faults({7, 7, 7}, 1) == 1);
    assert(clock_replace({7, 7, 7}, 1).faults == 1);
    assert(clock_replace({1, 2, 1}, 1).faults == 3);
    bool rejected = false;
    try {
        clock_replace(refs, 0);
    } catch (const std::invalid_argument&) {
        rejected = true;
    }
    assert(rejected);

    std::cout << "FIFO classic: frames=3 faults=" << fifo3
              << ", frames=4 faults=" << fifo4 << '\n';
    std::cout << "Clock trace:";
    for (int page : refs) {
        std::cout << ' ' << page;
    }
    std::cout << "\nClock frames:";
    for (const Frame& frame : result.frames) { // const & 表示这里只读页框。
        std::cout << ' ' << frame.page << '(' << frame.referenced << ')';
    }
    std::cout << " hand=" << result.hand << " faults=" << result.faults << '\n';
    std::cout << "checks passed\n";
}
```

### 按代码段理解

1. `fifo_faults` 用 `deque<int>` 保存装入顺序。`std::find` 返回迭代器，`end()` 表示没找到；命中直接 `continue`，因此队列顺序不会变。满时先弹队头，再装新页。
2. `Frame` 里 `occupied` 和 `referenced` 各有作用：前者判断有没有页，后者判断是否有近期访问信号。用单独的占用标记后，合法页号 0 不会和“空框”冲突。
3. `for (Frame& frame : result.frames)` 中的 `&` 让 `frame` 成为元素的引用。写 `frame.referenced=true` 才能修改原页框；如果写成按值 `Frame frame`，修改会落在副本里。
4. Clock 的 `while` 同时检查“有页”和“R=1”。空框直接退出循环，R=0 也直接退出；R=1 才清零并前移。`% capacity` 负责环形绕回，容量为 0 必须提前拒绝。
5. `Frame{page,true,true}` 的花括号按成员顺序设置页号、引用位、占用位。它替换的是现有框的内容，没有新增第 4 个页框。
6. 断言核对完整终态和缺页数，还有空访问、重复页、单框和零容量拒绝。这些是固定输入的正确性检查，不测真实内核缺页，也不是性能测试。

为了让初学者看清规则，两个函数都线性查找驻留页。设序列长 `n`、页框数 `k`，本实现总时间是 `O(nk)`，驻留状态空间 `O(k)`；它没有声称每次查找是 `O(1)`。Clock 的单次扫描也可能经过整圈，不能因指针只前进就说每次常数时间。

### 预期输出

这是固定输入的确定性结果。实际编译/运行记录统一见当天 `示例验证.md`。

## 6 淘汰不一定等于往磁盘写一页

实际选择还要看“这页离开后如何恢复”，缺页次数少也不等于总代价最低。

| 页面情况 | 可以怎样处理 | 为什么 |
| --- | --- | --- |
| 有可重新读取来源的干净文件页 | 回收时可以丢弃内存副本 | 后备内容仍在，需要时再读；不必先重复写一遍 |
| 修改过的文件页 | 通常需要适当回写后才能安全回收 | 最新内容还只在内存，直接丢掉会丢修改 |
| 仍需要保留的匿名内存内容 | 需要可用的交换等保存路径 | 它通常没有原文件可以直接重新读取 |
| 不可回收或被固定的页 | 不能按普通候选页任意淘汰 | 可能涉及设备使用、内核约束等 |

这里“匿名”指不由文件提供原始内容的映射，常见如堆、栈相关内存。Linux 对页面缓存、匿名页、可回收页有不同处理，不能只按一个页号队列包办。[Linux 内存概览：Page cache、Anonymous Memory、Reclaim](https://docs.kernel.org/admin-guide/mm/concepts.html)

“换出必然立即落到磁盘”也不准确。例如 Linux **zswap** 可以把交换页压缩存入 RAM 中的池，必要时才向后备交换设备回写；它用 CPU 压缩成本换取可能减少的交换 I/O。因此“移出普通驻留集合”“进入交换路径”“向物理存储设备写入”是不同层次的事件。[Linux zswap 文档](https://docs.kernel.org/admin-guide/mm/zswap.html)

## 7 Linux 与工程场景的边界

**不能回答“Linux 就是精确 LRU”或“Linux 就是这段 Clock”。** Linux 的回收实现与内核版本、编译配置和运行开关有关。Multi-Gen LRU 用“代”归组访问新旧程度相近的页，并结合访问类型等信息做选择；它不是给每次 CPU 访问都在一条精确链表上移动节点。[Linux MGLRU 设计文档](https://docs.kernel.org/mm/multigen_lru.html)

能否启用 MGLRU 还要看 `CONFIG_LRU_GEN` 等配置和 `/sys/kernel/mm/lru_gen/enabled` 等运行状态。这里仅解释读状态的依据，不自动修改用户机器配置。文档为滚动版，访问日 **2026-10-31**；具体机器以它的内核版本和配置为准。[Linux MGLRU 管理文档](https://docs.kernel.org/admin-guide/mm/multigen_lru.html)

对 C++ 服务开发的用途主要是理解现象：

- 同样的计算，在热数据已驻留和内存压力下反复缺页时，尾延迟可能很不一样。排查不能只看 CPU 函数本身耗时。
- 大量顺序扫描历史行情可能影响原来常用的数据驻留。应用缓存和 OS 页面回收不是同一层，但访问模式会影响双方。
- 缩小工作集、控制无界缓存、批量处理和改善局部性值得按实测选择。不能从本程序推出“Clock 在所有行情负载上比 LRU 好”。

## 8 自测、反例与口述

> [!question] 先自己回答
> Clock 为什么把命中页的 R 置 1？如果所有 R 都是 1，会不会死循环？FIFO 命中后把页移动到队尾还算 FIFO 吗？增加页框为什么不一定改善 FIFO？

> [!tip]- 核对
> R=1 告诉下一轮扫描它近期用过，给一次第二机会。本串行模型每经过一个 R=1 就清零，扫完一圈后可找到 0，不会死循环。FIFO 只保持装入顺序，命中不能挪队列。增加页框会改变后续淘汰顺序，FIFO 的不同容量集合不保证相互包含，经典序列得到 3 框 9 次、4 框 10 次缺页。

**约 60 秒口述：** 页面置换解决物理内存紧张时选择哪一页回收的问题。FIFO 按装入先后淘汰，简单但可能赶走热页，并可能出现增加页框反而增加缺页的 Belady 异常。LRU 用最近访问顺序，精确维护有成本；Clock 用环形指针和引用位近似近期使用，遇到 R=1 清零给第二机会，遇到 R=0 选作受害页。最优算法知道未来，通常用作离线比较。真实回收还要考虑脏页、页面类型和回写成本，干净文件页可丢弃，换出也不必马上写磁盘。Linux 实现要看版本和配置，不能用精确 LRU 或课堂 Clock 一句话概括。
