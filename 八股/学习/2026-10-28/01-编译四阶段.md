# 从源码到可执行文件：四个阶段

← [[学习/学习导航/2026-10-28-学习导航|返回导航]] · [[学习/2026-10-28/02-声明定义与ODR|下一节]] · [[八股测试/2026-10-28|今日自测]]

> [!abstract] 这一节要解决的问题
> 一个 main.cpp 包含头文件并调用函数，执行 g++ main.cpp -o app 时，从源文件到运行文件经历什么？-E、-S、-c 分别停在哪里？

## 先把词讲清楚

真实工程常有几十个 .cpp。编译器通常逐个处理它们，而链接器负责把调用与定义接起来。理解产物位置，才能根据报错阶段缩小范围。

| 术语 | 用普通话先理解 |
| --- | --- |
| 翻译单元 | 一个源文件连同其包含内容经预处理后形成的编译输入。 |
| 目标文件 .o | 尚未成为完整程序，保留符号与重定位需求的产物。 |
| 重定位 | 链接时把指令或数据中的地址引用调整到最终布局。 |

## 从具体故障理解机制

`#include` 是文本层面的引入；预处理完成后，每个 `.cpp` 拿到自身可见的声明。语义检查发生在编译阶段，例如参数类型不匹配。一个调用可以在本目标文件中暂时保留“尚未找到定义”的符号。汇编把指令变成机器码，链接再把这些待解决的名字连接到定义。

```mermaid
flowchart LR
  A["main.cpp + 头文件"] --> B["预处理：展开与选择"]
  B --> C["编译：语义检查与汇编"]
  C --> D["汇编：目标文件 .o"]
  D --> E["链接：解析符号与重定位"]
  E --> F["可执行文件"]
```

图里的箭头表示因果或构建顺序，不代表所有工具链内部必须分成完全相同的进程。回到问题：预处理处理 #include、条件编译和宏，得到翻译单元；编译将 C++ 语义分析并生成汇编；汇编形成含符号与重定位信息的目标文件；链接把多个目标文件和需要的库组合并解析引用，生成可执行文件。在 GCC 驱动中 -E 停在预处理、-S 停在汇编文本、-c 停在目标文件。编译通过不代表链接会通过，程序启动加载也不等于编译。

## 完整可运行代码

下面是 [[学习/2026-10-28/示例代码/01_build_stages|代码阅读版]] 的完整源码；保存的 `.cpp` 文件是编译验证对象。先按默认方式运行，再按场景修改宏或构建参数。每个语法点的作用也写在源码中文注释里。

```cpp
// 目的：观察宏、C++ 常量、函数声明/定义分别在哪个阶段发挥作用。
// 前置：会运行 g++；本文件独立可编译，推荐 C++17。
// 步骤：先预处理，再编译为 .o，最后链接运行；观察各产物。
#include <iostream>  // std::cout 输出最终计算结果。

#define MARKET_NAME "demo"  // 宏在预处理阶段做令牌替换，不具备 C++ 类型。

// 这是函数声明：告诉调用点参数与返回类型，但不提供函数体。
int quote_value(int price, int lot);

int main() {
    constexpr int lot = 100;  // C++ 常量有 int 类型，编译器会按语言规则检查。
    const int price = 3;      // const 表示不能通过这个名字修改 price。
    std::cout << MARKET_NAME << ':' << quote_value(price, lot) << '\n';
}

// 这是函数定义：链接时 quote_value 的引用最终需要找到这样的实现。
int quote_value(int price, int lot) {
    return price * lot;  // 这里只演示正常的小整数输入，不涉及溢出边界。
}
```

### 按代码逐步读

1. `#define MARKET_NAME` 会在预处理时替换；可用 `g++ -E` 查看结果，输出很长是因为标准头也被展开。
2. `constexpr int lot = 100` 是有类型的 C++ 常量，不能简单等同宏文本替换。
3. `main` 调用 `quote_value`；本文件同时提供定义，所以链接最终有着落。
4. `-c` 后看到的 .o 不可直接运行，仍可能含待解析引用。

## 在真实项目里怎样用

看到 `fatal error: xxx.h: No such file` 先查 include 路径；看到 `undefined reference` 先查定义是否参与链接；看到运行时找不到 `.so` 则是装载阶段。排查时保留完整编译命令和第一条错误，而不是只看 IDE 红线。

### 常见反例与边界

`g++ -E/-S/-c` 是 GCC 驱动选项，不是 C++ 语言标准规定的文件后缀流程。构建系统可能启用预编译头、unity build 或 LTO；它们改变实际步骤，但“谁需要看到声明，谁负责解析符号”仍可作为分析框架。

“四阶段”是常用教学模型；驱动可合并内部步骤，优化与 LTO 也会改变实际执行时机。

## 再做一个项目实验

### 动手观察四个停靠点

在示例代码目录运行下面命令，产物保存在临时目录。`-E` 把预处理文本写到 `stages.ii`，文件很长属正常现象；`-S` 产出汇编文本；`-c` 产出尚不能运行的对象文件；最后一条才生成程序。

```bash
d=$(mktemp -d)
g++ -std=c++17 -E 01_build_stages.cpp -o "$d/stages.ii"
g++ -std=c++17 -S 01_build_stages.cpp -o "$d/stages.s"
g++ -std=c++17 -c 01_build_stages.cpp -o "$d/stages.o"
g++ "$d/stages.o" -o "$d/stages"
"$d/stages"
```

`-S` 直接处理 `.cpp` 时驱动会完成必要的预处理和编译；不要理解为仅执行“第三步”。

## 30–90 秒口述与自检

**可以这样说：**先拆预处理、编译、汇编、链接；再用 -E/-S/-c 定位产物；最后根据报错所处阶段判断是头文件、语义、符号还是运行时依赖。

**自己再推一遍：**如果 `#if 0` 里写了非法 C++，为什么通常不会触发语法错误？如果删除 `quote_value` 的定义，哪一步报错？

**再追问：**追问：某行头文件没有被找到属于哪里？预处理阶段。函数只声明未定义为何能编译？调用点类型检查可过，最终链接找不到定义。
