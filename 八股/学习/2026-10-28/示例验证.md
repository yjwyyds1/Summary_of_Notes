## 环境

| 项 | 值 |
| --- | --- |
| 编译器 | `g++ (GCC) 13.1.0`（MinGW-w64），链接器 `ld.exe` |
| 标准 | `-std=c++17` |
| 优化 | 链接示例 `-O0`；微基准 `-O2` |
| 平台 | Windows 11，x86-64 |

## 结果

| 项目 | 结果 | 备注 |
| --- | --- | --- |
| 只编译 main 并链接 | **按预期失败** | `undefined reference to 'add(int, int)'` 与 `add_scaled(int, int)` |
| `nm -C main_only.o` | `U add` / `U add_scaled` | 证明编译产物里是未定义符号 |
| 两个 `.cpp` 一起链接 | 成功 | 输出 `add(1, 2) = 3`、`add_scaled(3) = 6` |
| `02_perf_benchmark` | 通过 | 不 reserve 4.30ms / 容量 2097152；reserve 2.90ms / 容量 2000000 |

## 说明

- “失败”是本示例的设计目标，不是环境错误；README 与正文都标明了这一点。
- 微基准只在本机、本编译选项下测了一次程序内部的 5 轮最小值，不代表跨平台结论。
- **没有做**：没有在 Linux + `ld` 上重复链接顺序实验；正文关于 `--start-group` 的说法来自 GNU ld 手册，未在本机验证（MinGW 的 `ld` 行为与 GNU ld 基本一致，但未实测）。
- **没有做**：没有演示 `multiple definition` 的实际报错文本；正文只描述原因，不虚构输出。
