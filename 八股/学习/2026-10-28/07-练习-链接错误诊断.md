# 练习：三个文件，四个症状，逐个定位

## 题目

一个最小工程包含 `main.cpp`、`math_util.h`、`math_util.cpp`，构建命令是：

```bash
g++ -c main.cpp -o main.o
g++ main.o -o app
```

运行后出现下面的报错：

```text
ld: main.o: in function `main':
main.cpp:(.text+0x18): undefined reference to `add(int, int)'
collect2: error: ld returned 1 exit status
```

请回答：

1. 这个错误发生在哪个阶段？`.o` 里 `add` 的符号状态是什么？
2. 有哪三种常见原因会造成它？分别怎么验证？
3. 如果同样的代码在 C 项目里能链接、C++ 里不行，最可能是什么问题？
4. 修好之后如果把 `math_util` 打成静态库，`g++ -lmathutil main.o` 与 `g++ main.o -lmathutil` 有什么区别？

## 先自己想

提示：链接器只认符号名，不看声明；`nm` 能看符号状态；静态库按从左到右扫描。

> [!tip]- 参考答案
>
> **1. 阶段与符号状态**
>
> 发生在链接阶段。`main.o` 里 `add` 是 `U`（undefined）——编译器看到了声明，生成了对 `add(int, int)` 的调用，但没有函数体。可以用 `nm -C main.o` 验证，本机输出：
>
> ```text
> U add(int, int)
> U add_scaled(int, int)
> ```
>
> **2. 三种常见原因**
>
> - **漏编译实现文件**：`math_util.cpp` 没有参与编译链接。验证：看命令行里有没有它，或 `nm math_util.o | grep add` 是否显示 `T`。
> - **链接顺序错误**：静态库 `-lmathutil` 放在 `main.o` 前面，扫描库时还没有未定义符号，成员不会被抽取。验证：调换顺序。
> - **符号名对不上**：C 与 C++ 混用、忘了 `extern "C"`，或函数签名与声明不一致（比如 `const`、默认参数以外的差异）。验证：`nm` 看库里的符号名是否带 `_Z` 修饰。
>
> **3. C 能链接、C++ 不行**
>
> 名字修饰。C++ 会把参数类型编进符号名（如 `_Z3addii`），而 C 库导出的是 `add`。在 C++ 侧用 `extern "C"` 声明，或者用带 `extern "C"` 的头文件。
>
> **4. 静态库的链接顺序**
>
> GNU ld 从左到右扫描：`g++ -lmathutil main.o` 在扫描库时还没有未定义符号，不会抽取成员，最终仍然 `undefined reference`；`g++ main.o -lmathutil` 先看到 `main.o` 的引用，再扫描库，才能正确抽取。
>
