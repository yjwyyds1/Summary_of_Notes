## 1 先用一个场景串起来

设想一个接收整数价格的小程序。有的处理器返回原价，有的加一，有的翻倍。我们希望调用方统一执行“处理一个价格”，不用在每个调用点重复写“如果是这个类，就调用这个函数”。

学习的不是加一和乘二算法，而是**怎样表达并保留不同实现**：

1. 具体处理器与通用处理器是什么类型关系？
2. 通过通用类型引用它时，会调用哪个实现？
3. 如何让编译器检查“我写的确实是覆盖”？
4. 如何规定具体实现必须提供哪些能力？
5. 如果通过通用类型拥有对象，最后如何销毁？
6. 保存对象时，有没有不小心把它变成一份普通基类值？

```mermaid
flowchart LR
    A["类型关系：继承或组合"] --> B["调用：静态或动态绑定"]
    B --> C["声明检查：override"]
    C --> D["能力约定：抽象接口"]
    D --> E["销毁：虚析构契约"]
    E --> F["保存：避免意外切片"]
```

## 5 每次只改变一个条件

学一段代码时，可以按下面的次序改动，先预测再运行安全版本：

- 只改变变量的声明类型，比较 Base 引用与 Derived 对象调用。
- 只改变函数是否 virtual，观察调用选择的区别。
- 只去掉派生函数末尾 const，判断是否仍覆盖；用 override 让编译器检查。
- 只改变参数按值还是按引用，观察是否创建了新的 Base 值。
- 比较“存 Base 值”与“拥有一个实际 Derived 对象”的集合。

涉及非虚基类删除、纯虚调用、越界或悬垂等反例时，做规则分析，不靠运行 UB 猜结果。源码中的错误行保持注释，不能把取消注释后的错误程序当成已验证示例。
