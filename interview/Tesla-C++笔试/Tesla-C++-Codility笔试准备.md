## 先学什么

1. **共享状态和 RAII**：先说清哪个 mutex 保护哪些字段。用 `lock_guard` 管简单临界区，函数抛异常时也会释放锁。等待要用 `unique_lock`，它允许条件变量临时释放锁。检查和修改关联字段放在同一临界区。
2. **条件变量和退出**：邮件里的 `cv.wait(mMutex, ...)` 是示意，实际传 `std::unique_lock<std::mutex>&`。如 `cv.wait(lock, [&]{ return closed || !queue.empty(); });`。谓词防虚假唤醒，状态在同一把锁下修改。关闭时唤醒全部等待者，先约定积压任务如何处理，再决定何时返回。限时等待优先使用谓词重载。
3. **对象生命周期和异常**：创建线程前初始化它访问的状态，关闭时先唤醒再 join，join 时别持有工作线程需要的锁。在线程入口捕获需要处理的异常，异常若逃出线程入口会触发 terminate。明确失败后计数、队列和资源仍处于什么状态。单独所有权用 unique_ptr，确需共享生命周期再考虑 shared_ptr，指向的可变对象仍需要同步。
4. **多个锁和原子**：用 scoped_lock 同时获取多个 mutex，避免调用链中锁序反转。独立统计计数可用 atomic，涉及多个字段或容器的不变量先用 mutex。shared_mutex、timed_mutex、recursive_mutex 留在能说明用途时使用。先练正确退出和异常安全，再补内存序。

## 三轮练习

- **第一轮，45–60 分钟**。写线程安全任务队列。接口 push、pop、close。关闭前 pop 等待，关闭后拒绝 push，积压读完后 pop 返回空。测 FIFO、空队列等待、关闭唤醒、重复关闭、关闭前入队可读。两生产者两消费者检查每个任务 ID 恰好处理一次，多个消费者下按队列出队语义判断 FIFO，别用处理完成顺序判断。
- **第二轮，45–60 分钟**。写最多 N 个并行租约的资源池。acquire_for 成功返回可移动 RAII 租约，超时返回空。释放一次后可以再借，移动后原对象不归还，任务抛异常也归还。明确 N=0 的处理、池与租约的生命周期约束。记录最大同时租用数，确保不超过 N。
- **第三轮，80 分钟闭卷模拟**。实现 2 个 worker 的任务执行器，提供 submit、stop。先明确接收、执行、关闭的契约。关闭后拒绝提交，已接收任务执行完毕，单个任务抛异常后下一个任务仍能跑，stop 重复调用也安全。本练习约定由一个控制线程调用 stop，工作线程不会调用 stop。至少覆盖零任务、积压关闭、抛异常、并发提交和关闭；记录提交被接受的 ID，与最终执行 ID 对账。需要精确触发并发顺序时用 promise/future 或条件变量做同步点。

本地用 `g++ -std=c++17 -Wall -Wextra -Wpedantic -pthread main.cpp -o practice.exe`。有 3 天时，每天一轮。只剩 1 天时，先做第一轮，再做第三轮，留 15 分钟复盘。练习合格线是从空文件写出能编译的主路径，能解释共享状态、关闭语义和异常行为，并通过上述测试。
